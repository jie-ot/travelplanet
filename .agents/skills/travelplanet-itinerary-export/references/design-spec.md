# 行程长图设计规范

## 内容结构

长图包含以下四级内容：

1. 主标题：目的地或简短行程主题。
2. 副标题：日期、天数。
3. 旅行概览：景点清单和美食清单；没有确认的美食时省略美食行。
4. 总日程卡：把全部日期排在同一张卡片中。每天显示日期、标题，并按 `schedules` 数组顺序列出全部日程节点。

旅行概览必须从结构化行程提取事实：

- 景点：从各天景点类日程的 `place_name` 按出现顺序去重。用 `tags` 区分景区与大交通/住宿/餐饮；tag 缺失时宁可少列，不要把机场算进景点。
- 美食：以 `food_recommendations` 为主，餐饮类日程店名/菜名可并入去重。没有就整行不画，不写“当地特色”。只去掉名称前缀「推荐」。

每日日程不是一句话概括，也不是 2–4 个核心节点。按当天数组顺序全部列出，这就是先去哪、后去哪。

每个节点：

- 有 `start_time`/`end_time`：写时间范围和停留（`end - start`）。
- 只有 `time_period`：不要编停留时长。
- `travel_minutes` 是到该点的路途，写成“步行 20 分钟前往…”。
- 大交通和酒店入住/退房写进当日怎么走。

不要展示车次、航班号、座位、舱位、登机口、检票口、预订号、票价、坐标、`fact_refs`、天气、准备事项、`bookings` 细节、`experience_summary` 正文、地图字段或未验证备注。

不要用省略号截断。一行放不下就换行；标题过长换行或略缩字号。

总日程卡使用细分隔线、编号和窄色条建立顺序。不要绘制箭头、连接线或独立路线清单。

## 字数与密度

文字量由天数和全部日程决定，不添加介绍文字凑数，也不为了紧凑而删掉主景点。

- 主标题完整显示，优先缩小字号或换行。
- 副标题一行或自然换行，不重复天数。
- 日标题删除括号内天气备注，过长时换行，不用省略号。
- 画布宽 1080 px，高度按内容计算，上限 18000 px。

## 画布与网格

默认使用 1080 px 宽的高分辨率画布，左右安全边距 56–72 px，模块间距 16–24 px。画布高度按内容动态计算。

推荐结构：

1. 标题区：主标题与副标题。
2. 概览卡：用两行分别展示景点和美食；没有美食时只保留景点行并自动收紧高度。
3. 日程主体：所有日期集中在一张总日程卡中，按天纵向排列，每天下列出全部节点。
4. 极简底部：可仅保留细分隔线或小型品牌署名。

总日程卡不随天数拆分。每行左侧放日期标记与日标题，下方按顺序排列当天全部日程。

## 卡片规范

- 卡片圆角建议 20–28 px。
- 卡片内边距建议 24–32 px。
- 日标题与节点之间保持清晰间隔。
- 路途说明使用较浅颜色，与停留/活动区分。
- 每张卡片最多使用一个强调色，不给不同卡片随机分配颜色。
- 禁止任何景点箭头或路线连接线。

## 字体与色彩

主标题使用支持中文且识别度高的展示字体、楷体或宋体回退，建议字号 58–76 px。副标题建议 24–30 px，正文建议 22–26 px；在约 360 px 宽预览中仍须清晰。

沿用 TravelPlanet 的米白、蓝绿色和珊瑚橙。整张图限制为一个主色、一个强调色和中性色。使用纯色或极轻的色块，不使用照片、插画、纹理、风景剪影、渐变主视觉或图片占位符。

## 视觉验收

实际查看生成的 PNG，而不只是页面 DOM：

1. 按原始尺寸检查中文字体、边缘清晰度和卡片对齐。
2. 缩放到约 360 px 宽，确认标题和日程节点仍可阅读。
3. 确认主标题和副标题完整显示，没有省略号，也没有重复天数。
4. 确认“景点”“美食”文字在胶囊标签内水平与垂直居中。
5. 快速扫视应能识别目的地、日期、游玩景点、品尝美食，以及每天先去哪、后去哪、停多久。
6. 确认所有日期处于同一张总日程卡，且不存在箭头路线。
7. 确认页面没有图片区或由其遗留的空白。
8. 检查长地名、七天以上、某天节点很多、没有美食数据和只有一天等边界情况。
9. 确认景点/美食/每日节点都能在 JSON 里找到对应项，且没有 JSON 里没有的内容。

只有实际 PNG 通过这些检查后，才判定长图设计完成。
