# 腾讯云轻量服务器部署

本文用于将发布包部署到 Ubuntu 服务器
`114.132.201.196`，固定应用目录为
`/home/ubuntu/travelplanet_backend`，服务端口为 `8000`。

## 发布包边界

发布包是当前本地后端的完整可运行快照，包含：

- 源码、`uv.lock`、Alembic 迁移和 systemd 模板；
- 当前 `.env` 及其中的密钥；
- 当前 SQLite 数据库；
- 当前用户上传图片和已生成图片。

发布包不包含 `.venv`、缓存、日志和测试目录。发布包等同于敏感
备份，不得提交到 Git、发送给无关人员或放到公开下载地址。

本次升级以发布包内的本地当前数据为准。云端旧数据只做完整备份，
不合并到新版，以免覆盖或混杂当前本地数据。

## 1. 上传前检查服务器

先不要删除或覆盖旧目录。在服务器终端执行：

```bash
whoami
cd /home/ubuntu
pwd
df -h /
python3 --version
node --version
npx --version
uv --version
command -v node
command -v npx
command -v uv
systemctl list-units --type=service --all | grep -Ei 'travel|uvicorn|gunicorn' || true
ps -ef | grep -E '[u]vicorn|[g]unicorn|[p]ython.*app.main' || true
sudo ss -lntp | grep ':8000' || true
curl -fsS http://127.0.0.1:8000/openapi.json | head -c 200
```

要求 Python 不低于 3.11，Node.js 不低于 20.9。记录当前占用
8000 端口的服务名或进程启动方式。如果 `node` 或 `npx` 位于
`/home/ubuntu/.nvm/`，还需把它们所在的 `bin` 目录加入第 8 步
systemd 文件的 `Environment=PATH=...`。

## 2. 上传并校验发布包

使用 OrcaTerm 文件管理器，把发布包上传到 `/home/ubuntu/`，
然后执行：

```bash
cd /home/ubuntu
umask 077
sha256sum travelplanet_backend_deploy_20260728.tar.gz
tar -tzf travelplanet_backend_deploy_20260728.tar.gz | head -n 30
chmod 600 travelplanet_backend_deploy_20260728.tar.gz
```

`sha256sum` 必须与发布电脑给出的值完全一致。

## 3. 解压到新目录

```bash
cd /home/ubuntu
test ! -e travelplanet_backend_new
mkdir travelplanet_backend_new
tar -xzf travelplanet_backend_deploy_20260728.tar.gz \
  -C travelplanet_backend_new
```

若 `test ! -e` 没有通过，先暂停并检查该目录，不要直接删除。

## 4. 安装新版依赖

```bash
cd /home/ubuntu/travelplanet_backend_new
uv sync --frozen --no-dev
```

这一步不影响正在运行的旧版。完成后应存在
`/home/ubuntu/travelplanet_backend_new/.venv/bin/python`。

## 5. 停止旧服务并备份

将下面的 `<旧服务名>` 替换为第 1 步查到的真实 systemd 服务名：

```bash
sudo systemctl stop <旧服务名>
sudo ss -lntp | grep ':8000' || true
cd /home/ubuntu
backup_dir="travelplanet_backend_backup_$(date +%Y%m%d_%H%M%S)"
cp -a travelplanet_backend "$backup_dir"
echo "$backup_dir"
```

如果旧版不是 systemd 管理，先按其真实启动方式停止。确认 8000
端口已释放后再继续。备份目录应完整包含旧代码、`.env`、数据库和图片。

## 6. 检查包内密钥与当前数据

```bash
cd /home/ubuntu
chmod 600 travelplanet_backend_new/.env
test -s travelplanet_backend_new/.env
test -s travelplanet_backend_new/data/travelplanet.db
find travelplanet_backend_new/static/uploads \
  travelplanet_backend_new/static/generated -type f 2>/dev/null | wc -l
```

不要使用 `cat .env`，避免密钥出现在终端历史或截图中。
`RAIL_MCP_ENDPOINT` 应写成
`RAIL_MCP_ENDPOINT=stdio:npx -y 12306-mcp`，不要添加外层引号；
Docker 的 `--env-file` 会把外层引号作为变量值的一部分。

## 7. 切换目录并升级数据库

```bash
cd /home/ubuntu
mv travelplanet_backend travelplanet_backend_old
mv travelplanet_backend_new travelplanet_backend
cd travelplanet_backend
.venv/bin/python -m alembic upgrade head
.venv/bin/python -m alembic current
```

预期当前迁移为：

```text
b824c31f5a21 (head)
```

## 8. 安装并启动统一的 systemd 服务

```bash
cd /home/ubuntu/travelplanet_backend
sudo cp deploy/travelplanet-backend.service \
  /etc/systemd/system/travelplanet-backend.service
sudo systemctl daemon-reload
sudo systemctl enable --now travelplanet-backend.service
sudo systemctl status travelplanet-backend.service --no-pager
```

如果第 5 步的旧服务名不同，确认旧服务已禁用，避免重启后抢占端口：

```bash
sudo systemctl disable <旧服务名>
```

## 9. 验证

```bash
curl -fsS http://127.0.0.1:8000/openapi.json >/dev/null \
  && echo "local backend OK"
curl -fsS http://114.132.201.196:8000/openapi.json >/dev/null \
  && echo "public backend OK"
sudo journalctl -u travelplanet-backend.service -n 80 --no-pager
```

再从发布电脑访问：

```text
http://114.132.201.196:8000/docs
```

## 10. 失败时回滚

不要删除任何备份。先停止新版：

```bash
sudo systemctl stop travelplanet-backend.service
cd /home/ubuntu
mv travelplanet_backend travelplanet_backend_failed
mv travelplanet_backend_old travelplanet_backend
```

然后按旧版原来的服务名或启动命令恢复。若新版已执行数据库迁移，
旧代码无法读取新增字段时，使用第 5 步完整备份目录中的旧数据库恢复；
不要直接运行 Alembic downgrade。
