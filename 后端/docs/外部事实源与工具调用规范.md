# 🪐《旅行星球》外部事实源与工具调用规范

> **本文按当前代码描述运行时事实**：规划 Function Calling 白名单、内部研究协议、高德 REST、铁路社区 MCP、参数 Schema、失败降级、事实引用、审稿补查与日志。前后端 DTO、数据库表结构和 vivo Chat 协议分别见其他规范。
>
> 工具能力不得改变前后端接口；模型只能提出白名单调用，实际参数校验、执行和降级统一由 `travel_fact_service.execute_tool()` 完成。

## 一、当前边界

1. 正常 `/api/ai/planning` 不预取事实包：`needs_facts()` 恒为 `False`，`build_fact_pack()` 只保留为空包兼容函数。
2. 外部事实只在 `orchestrator._plan_with_tools()` 的研究协议中获取。endpoint、前端、Prompt 或其他 Service 不直接 import Provider。
3. 当前固定走 Function Calling；只有调用 `plan_itinerary(..., execute_tool=None)` 时才走无工具 plain JSON 分支，正常 `planning_service` 始终传入执行器。
4. 工具结果和模型输出都不作为天然可信输入：外部参数先经 Pydantic；结果由 Provider 转为受控 dict/Schema，候选事实注册请求级 `fact_id`。
5. 工具失败通常变成 `unknown`、`provider_not_connected`、`needs_official_confirmation` 或结构化 `error` 回填模型，不单独使接口失败。只有未被业务层捕获的异常才可能最终映射为 `1003`。
6. 当前不引入 RAG、向量数据库、开放式搜索、浏览器抓取或模型自由联网。

## 二、模型可见工具白名单

当前 `PLANNING_TOOLS` 恰有 8 个工具：3 个内部编排工具和 5 个外部工具。

| Function | 类型 | 参数要点 | 实际行为 |
|---|---|---|---|
| `declare_trip_scope` | 内部 | `origin`、`destinations`、起止日期、交通/酒店需求、兴趣、不确定项 | 保存模型理解的旅行范围；必须先于 `finish_research`，不访问 Provider |
| `update_planning_fact_state` | 内部 | `selectedFactIds`、`remainingQueries` | 从事实注册表保留完整事实并记录后续查询；未知 ID 返回 `partial` |
| `finish_research` | 内部 | `completed`、`unresolved`、`outline` | 关闭工具研究；必须已声明范围，且不得与外部调用同轮成功结束 |
| `amap_weather_range` | 外部 A 类 | `city/startDate/endDate` | 一次高德预报请求整理连续日期；范围最多 14 天 |
| `amap_poi_search` | 外部 A 类 | `keyword`、可选 `city` | 高德关键词 POI 搜索，当前最多返回 8 条 |
| `amap_poi_around` | 外部 A 类 | `location/keywords`、可选 `radius/city` | 高德周边 POI，当前最多返回 8 条；半径默认 1000 米、最大 50000 米 |
| `amap_route` | 外部 A 类 | 名称或 `originLocation/destinationLocation`、`mode`、可选 `city` | 高德驾车/公交/步行/骑行路线，返回一条距离和时长事实 |
| `query_rail_tickets` | 外部 A′ 类 | `origin/destination/date` | 社区 12306 MCP，最多整理 16 个参考候选，并始终附 12306 官方入口 |

外部参数当前只做类型、必填和非空校验；`amap_weather_range` 与铁路日期没有在参数 Schema 层强制正则。天气 Provider 会用 `date.fromisoformat()` 解析，失败时返回 `unknown`。

## 三、当前已删除或未接入的能力

1. **机票 MCP 已删除**：当前没有 `flight_mcp_provider.py`、`FlightFact`、`query_flights`、`FLIGHT_MCP_*` 配置或机票执行分支。文档、验收和日志不得声称当前会查询航班。
2. `qweather_provider.py` 和 `QWEATHER_*` 配置仍在，但没有加入 `PLANNING_TOOLS` 或 `execute_tool()`，当前规划不会调用。
3. `AMAP_MCP_ENABLED`、`AMAP_MCP_SSE_URL` 只是配置预留；`amap_provider.py` 固定走 REST，不读取它们。
4. `entry_guides.py` 仍定义铁路、机票/酒店、本地生活三个本地模板；当前执行器只在铁路查询未启用/失败/空结果时调用 `rail_entry_guide()`。机票/酒店和本地生活模板当前没有运行时调用点。
5. 高德详情、距离测量、IP 定位等能力没有注册为 Function；地理编码只作为路线/周边查询的内部辅助。

## 四、Provider 与结果结构

### 4.1 高德 REST

高德仅在 `TOOLS_ENABLED=true` 且 `AMAP_API_KEY` 非空时可用。调用地址由 `AMAP_BASE_URL` 与以下路径拼接：

- 天气 `/v3/weather/weatherInfo`
- POI 文本 `/v3/place/text`
- POI 周边 `/v3/place/around`
- 地理编码 `/v3/geocode/geo`
- 路线 `/v3/direction/{driving|walking|bicycling|transit}`

所有 REST 请求受 `AMAP_MAX_QPS` 全局滑动窗口节流；网络临时错误最多按 `TOOL_MAX_RETRY` 额外重试，非 200、Provider `status != 1` 或其他异常直接返回空结果并降级。

主要 Schema：

```python
FactStatus = Literal[
    "ok", "unknown", "timeout",
    "provider_not_connected", "needs_official_confirmation",
]

class WeatherFact(BaseModel):
    city: str
    date: str
    summary: str | None
    status: FactStatus

class PoiFact(BaseModel):
    name: str
    address: str | None
    location: str | None
    category: str | None
    status: FactStatus

class RouteFact(BaseModel):
    origin: str
    destination: str
    mode: Literal["driving", "transit", "walking", "bicycling"]
    distance_km: float | None
    duration_minutes: int | None
    status: FactStatus
```

路线解析规则：已提供 `lng,lat` 时坐标直通；名称输入先解析坐标。酒店、餐厅、车站、机场、码头等商业/交通 POI 优先走 POI 文本搜索，普通地址优先 geocode，失败再用 POI 搜索。公交路线可使用 `city`/adcode。

### 4.2 铁路社区 MCP

铁路只有在 `TOOLS_ENABLED=true`、`RAIL_MCP_ENABLED=true` 且 `RAIL_MCP_ENDPOINT` 非空时尝试。当前 `Settings` 与 `.env.example` 的默认 endpoint 均为：

```env
RAIL_MCP_ENDPOINT=stdio:npx -y 12306-mcp
```

适配器同时兼容两套 stdio 工具：

- endpoint 含 `12306-mcp` 且不含 `mcp-server-12306`：Node 工具 `get-station-code-of-citys` → `get-tickets`；
- 其他 endpoint：drfccv 工具 `search-stations` → `query-tickets`。

候选按 07:00–22:00、小时覆盖、历时和车次等级筛选，最多 16 条。`RailFact.status="ok"` 仍只是参考级：

```python
class RailFact(BaseModel):
    origin: str
    destination: str
    date: str
    train_no: str | None
    depart_time: str | None
    arrive_time: str | None
    duration: str | None = None
    seat_class: str | None
    ref_price: float | None
    source: str = "community_mcp"
    status: FactStatus
```

成功结果包含 `reference=true`、`disclaimer`、`official_entry`、`recommended` 和候选列表；模型必须注明以 12306 官方实时信息为准。未启用、启动中、失败、超时、空结果或结构变化时返回 `needs_official_confirmation` 的铁路官方入口，不抛出 Provider 异常。

## 五、MCP 会话与启动

`mcp_stdio.py` 只接受 `stdio:` endpoint，在独立事件循环线程维护持久会话。单次调用最多等待 `TOOL_TIMEOUT_SECONDS`；失败后按 `MCP_UNAVAILABLE_TTL_SECONDS` 缓存不可用状态。

`main.py` 在 lifespan 中预热已启用的铁路 endpoint。`MCP_WAIT_READY_ON_STARTUP=true` 时，应用启动会等待 `ready/failed/invalid/timeout`，上限约为 `MCP_STARTUP_TIMEOUT_SECONDS + 1` 秒；失败只记录警告，不中止启动。若关闭启动等待，请求在线程仍处于 `starting` 时会立即拿到空结果并降级。

当前相关配置：

```env
TOOLS_ENABLED=true
AMAP_API_KEY=
AMAP_BASE_URL=https://restapi.amap.com
AMAP_MAX_QPS=3
AMAP_MCP_ENABLED=true
AMAP_MCP_SSE_URL=https://mcp.amap.com/sse
QWEATHER_API_KEY=
QWEATHER_BASE_URL=https://devapi.qweather.com
RAIL_MCP_ENABLED=true
RAIL_MCP_ENDPOINT=stdio:npx -y 12306-mcp
TOOL_TIMEOUT_SECONDS=20
TOOL_MAX_RETRY=1
MCP_WAIT_READY_ON_STARTUP=true
MCP_STARTUP_TIMEOUT_SECONDS=60
MCP_UNAVAILABLE_TTL_SECONDS=120
```

其中高德 MCP 与和风配置不代表当前已接入能力；`.env.example` 当前未列出 `MCP_UNAVAILABLE_TTL_SECONDS`，未设置时使用 `Settings` 默认 120 秒。

## 六、研究协议、事实注册与审稿

1. 研究最多 8 个模型轮次；没有 tool call 的提前正文会被追加提示并要求继续研究。
2. 研究阶段外部调用累计最多 75 次，按每个外部 tool call 计数。缓存键为“工具名 + 参数排序 JSON”；缓存命中仍会在查缓存前占用一次计数。
3. Provider 结果中的 `pois`、`days`、`candidates`、`recommended` 分项获得 `fact_{tool}_{12位UUID}`。没有这些分项时整个结果获得一个 `fact_id`。
4. `update_planning_fact_state` 只按 ID 保留注册表中的完整事实；未选事实不进入最终紧凑上下文。模型未显式保留任何事实时，结束研究后回退为保留全部注册事实。
5. 未调用 `declare_trip_scope` 或未成功调用 `finish_research`，研究直接以 `1001` 失败；达到轮次/调用上限不会自动替模型完成 `finish_research`。
6. 工具关闭后生成完整 `ItineraryData`；解析失败只做一次无工具 JSON 修复。
7. 对初稿再进行一次低温审稿。审稿最多提出 8 个白名单补查；这些补查复用请求内缓存，但当前代码没有把它们计入研究阶段的 75 次上限。只有注册到新增事实才完整重生成一次。
8. 审稿返回空内容/非法 JSON，或补查没有新增事实时，保留已经通过解析的初稿。

## 七、事实状态与对外措辞

| 状态/来源 | 允许表达 | 禁止表达 |
|---|---|---|
| 高德 `ok` | 可引用返回的地点、距离、预计时长、天气摘要 | 超出返回字段的细节 |
| 铁路 `ok` | 可给参考车次/时刻/参考票价，并显式注明以 12306 官方实时为准 | 确定余票、可订、最终价格 |
| `unknown` / `provider_not_connected` | 建议用地图、天气或官方渠道确认 | 编造精确事实 |
| `needs_official_confirmation` | 给出 12306 官方查询入口和查询条件 | 声称已经完成实时查询 |
| 工具 `error` | 说明无法核验并建议官方确认 | 把错误结果当事实 |

`Schedule.fact_status`、`fact_refs` 等增强 DTO 字段由模型填写；当前 `itinerary_validation_service.py` 不核验引用 ID 是否存在，也不扫描正文中的航班号、价格或余票，因此这些约束主要由 Prompt、研究协议和审稿保障，不是确定性内容过滤。

## 八、日志与错误边界

每次外部调用以及白名单/参数错误都尽力写 `tool_call_logs`。当前持久化字段包括 `request_id/task_type/tool_name/provider/input_summary/output_summary/status/degraded_to_b/latency_ms/error_code`；状态归一化为 `success/timeout/failed/fallback`。

输入/输出会经 `_diagnostic_value()` 限制深度、键数、列表数和字符串长度，但会保留具体查询参数、验证错误、Provider 事实摘要和执行异常文本。业务 JSONL 日志还会记录工具摘要；两类日志都不得含 API Key、access token、用户照片 base64 或隐性特质全文，并应作为敏感本地数据保护。数据库日志写入失败只记录应用错误，不改变规划结果。

工具失败默认不直接产生前端业务码；模型研究协议本身未完成、最终 JSON 失败或业务校验失败映射 `1001`，配置/未处理内部异常映射 `1003`，请求 DTO/空 message 映射 `1002`。

## 九、实现验收清单

复核当前实现时必须确认：

1. `PLANNING_TOOLS` 为 3 个内部 + 5 个外部工具，不含机票；
2. `needs_facts()` 为 false，正常首轮不注入 `TravelFactPack`；
3. 高德固定走 REST，和风/高德 MCP 未注册；
4. 铁路失败静默回退 12306 入口，并保留参考级免责声明；
5. 研究必须声明范围并显式结束，轮次/调用/审稿补查边界与本文一致；
6. 事实按 `fact_id` 注册、选择、裁剪，最终生成阶段工具关闭；
7. 外部调用和参数/白名单错误尽力写日志；
8. 工具故障不会单独使接口失败，也不会改变前后端 DTO。
